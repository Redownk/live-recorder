# Live Recorder

基于 FastAPI 的轻量多直播平台录制平台，支持抖音、哔哩哔哩、斗鱼直播间管理、直播检测、后台监控录制和 SQLite 持久化。不需要 Redis 或 MySQL。

## 启动后端

```powershell
python -m pip install -r requirements.txt
python run.py
```

FastAPI 只提供 API，默认地址为 `http://127.0.0.1:8000`，接口文档在 `http://127.0.0.1:8000/docs`。

后端必须单进程运行（`workers=1`），一个进程可以并发录制多个直播间。
启动入口已固定单进程；同一 SQLite 数据库旁的 `.lock` 文件使用操作系统文件锁，
阻止第二个后端实例使用该数据库，退出或进程崩溃后锁自动释放，无需删除锁文件。
多进程、多机器部署不属于当前运行方案。

## 启动前端

独立 Vue 项目位于 `frontend/`，使用 Vue 3、Vue Router 和 Vite。
需要 Node.js 20.19+（20.x）或 22.12+。

在另一个终端运行：

```powershell
cd frontend
npm ci
npm run dev
```

前端默认访问地址为 `http://127.0.0.1:5173`。端口占用时 Vite 会显示实际使用的端口。
开发服务器将 `/api`、`/crawler`、`/live`、`/actuator` 代理到后端，不需要单独配置浏览器跨域。

前端配置、构建和部署方式见 [frontend/README.md](frontend/README.md)。

## 配置

### Windows EXE

先在 `frontend/` 执行 `npm ci`、`npm run build`，然后在项目根目录的虚拟环境中运行：

```powershell
python -m pip install pyinstaller
python -m PyInstaller --clean --noconfirm LiveRecorder.spec
```

生成 `dist/LiveRecorder.exe`，包含 Vue 静态文件、Python 后端和 FFmpeg / FFprobe。
`.spec` 中显式收集 `aiosqlite`、SQLite 异步方言和 `greenlet`；构建环境必须已安装
`requirements.txt`。如果构建电脑的 FFmpeg 安装位置变化，需要调整 `.spec` 的工具路径。
Vue 使用相对 API 地址（不要设置指向开发服务器的 `VITE_API_BASE_URL`）。
双击 EXE 后，在浏览器访问 `http://127.0.0.1:8000`，不需要启动 5173。
前端历史路由可直接访问或刷新；现有 API 和接口文档路径不变。
控制台按 Ctrl+C 正常退出并清理后台任务。

打包资源从 EXE 临时解压目录读取；可写数据默认保存在 EXE 所在目录，
首次运行生成 `config.yaml`，已有配置不覆盖。相对 SQLite 路径及录制路径以该数据目录为基准，
不会写入临时解压目录。EXE 所在目录必须可写，也可通过 `LIVE_RECORDER_DATA_DIR`
指定另一个可写目录。已有数据库不会自动从源码项目复制或迁移，需先停止旧程序，
再将数据库放到新数据目录的 `data/` 下，并检查原录制保存路径。

可在独立临时数据目录执行打包自检；自检会初始化该目录的数据库、检测前端及内置工具后退出，
不启动监听端口，不打开浏览器，不自动监控直播间：

```powershell
$env:LIVE_RECORDER_DATA_DIR = "$env:TEMP/live-recorder-self-test"
.\dist\LiveRecorder.exe --self-test
Remove-Item Env:LIVE_RECORDER_DATA_DIR
```

### 运行配置

主要配置在 `config.yaml`：

- `database.url`: 默认使用 `sqlite+aiosqlite:///./data/live_recorder.db`
- `platforms`: 各平台 Cookie

检查状态和录制任务按 `(platform, room_id)` 保存在进程内，同一直播间不会重复启动。
不再需要锁续期，录制任务从准备、录制到合并完成前始终保持登记，结束或失败后清理。
页面「停止监控」会取消检查和所有当前录制，等待 FFmpeg 退出及日志清理后返回。
中断的录制保留分片，不执行合并；再次启动监控时重新检查并开始新的录制。
关闭后端同样会取消检查和录制任务，等待 FFmpeg 退出后再关闭数据库。
启动时会将遗留的未结束日志标记为「录制中断」，不伪造结束时间和录制时长，
也不会自动续录或删除旧分片；监控启动后会重新检测直播间并开始新录制。

直播间支持最多 512 字的备注，可在添加或编辑直播间时填写，也可在列表「备注」列直接
修改、保存或清空。搜索支持备注，已有数据库启动时自动补充备注字段，不改变原记录。
新增直播间未填写备注时，自动使用 checker 获取的主播名（`owner`）作为初始备注。
添加时填写的自定义备注会保留；默认值只在添加时设置，后续修改、清空或主播名变化不会覆盖备注。

直播间列表显示实际录制状态和本次录制时长。FFmpeg 录制进程启动后显示「录制中」，
断流等待重连时显示「重连中」，结束录制后显示「未录制」，合并阶段不计入录制时长。
时长从本次首次启动录制进程开始计算，重连不重置，包含重连等待时间。
页面每 3 秒通过 `GET /api/recording-status` 同步状态，时长逐秒更新；请求失败时显示状态不可用。
状态保存在当前 FastAPI 单进程内存中，不依赖直播检测结果，服务重启后重置。

## 录制设置

前端「设置」页可修改保存目录、文件名模板和直播检查周期。设置通过
`GET /api/settings`、`PUT /api/settings` 保存到 SQLite，重启后保留。
`POST /api/settings/preview` 只计算文件名和目录，不创建文件或保存设置。

默认保存目录为项目根目录下的 `record/`，相对路径以项目根目录为基准。
前端填写的是后端主机上的路径；保存时会创建目录并检查写入权限。
保存路径右侧的文件夹按钮可打开目录选择窗口，浏览本机盘符、进入子目录、返回上级、
直接输入路径或切换到项目/用户目录。选择当前目录只更新表单，点击「保存设置」才持久化。
目录浏览只列出文件夹，不读取文件内容，也不会创建目录；只允许后端本机和本机页面访问。
浏览器与后端不在同一台电脑时，这不是浏览器电脑的原生目录选择器；远程访问仍可手动填写后端保存路径。
目录和命名规则影响下一次开始的录制，已开始的录制继续使用原文件路径。

默认命名模板是 `{platform}_{owner}_{timestamp}`，还支持 `{remark}`、`{room_id}`、`{title}`、
`{date}`、`{time}` 和 `{record_id}`。文件名自动过滤非法字符、限制长度，
不再自动追加唯一编号，只有显式使用 `{record_id}` 才会包含该编号；分段后缀和最终扩展名由录制器生成。

命名模板支持用 `/` 创建子目录，最后一段为文件名。例如 `{owner}/{timestamp}`
生成 `保存目录/主播名/日期时间.ts`，`{platform}/{owner}/{date}/{timestamp}`
可按平台、主播和日期逐层归档。录制开始时自动创建目录。同名录制会报错并保留已有文件，
建议规则包含 `{timestamp}`，多个直播间共用目录时可加 `{room_id}` 区分。
每层目录和文件名分别清理非法字符，变量内的斜杠不会生成目录；模板不允许绝对路径、
空目录、`.` 或 `..`，也不会通过已有符号链接写到保存目录以外。

`{remark}` 使用直播间备注，如 `{remark}/{owner}_{timestamp}` 或 `{owner}_{remark}_{timestamp}`。
空备注替换为 `未备注`。备注修改影响下一次开始的录制，不重命名已开始或已完成的文件。

检查周期单位为秒，范围 1 至 86400，默认为 5。每轮检查完成后等待设定时间；
修改周期会唤醒等待中的爬虫，停止监控也无需等待整个周期。
此设置不改变录制中断后的重试等待时间或统计采集周期。

### 磁盘空间保护

设置页可查看当前生效保存目录及活动录制目录的剩余容量，并配置空间保护：

- 默认启用，`disk_min_free_gb=5`：低于 5 GiB 告警并阻止新录制，不影响已有录制。
- `disk_stop_free_gb=1`：低于或等于 1 GiB，停止对应目录上的录制并保留分片。
- 停止阈值必须小于暂停新录制阈值，单位为 GiB（1024 的三次方字节）。
- 开始录制前检查空间；后台每 5 秒检查活动录制目录。不能读取磁盘容量时阻止新录制，
  并停止受影响目录上的活动录制。保护不是磁盘配额，突发大规模写入仍可能耗尽空间。
- 修改保存目录不会改变已有任务的保护目标，旧目录仍继续检查；不删除任何已有视频。
- 自动分片合并前额外估算输出所需空间，空间不足则保留原分片、不合并。

阈值保存到 SQLite，旧数据库启动时自动补充字段。释放空间至暂停阈值以上（含等于）后，
下一次自动检查可重新开始录制；全局监控未启动或房间监控已关闭时不会自动开始。
本保护针对直播录制及其自动合并，不控制独立「视频处理」任务。
磁盘容量接口：`GET /api/settings/disk`。

### 单直播间控制

直播间操作列新增立即录制与停止按钮，三个平台共用同一任务管理机制：

- 立即录制：调用对应 checker 检查，开播才创建录制任务；未开播返回提示。
  不修改该房间的监控开关，也不会启动全局监控。检查超时为 30 秒。
- 停止并暂停监控（默认）：取消该房间的检查、录制或自动合并，并关闭房间监控。
- 停止本次，保留监控：只结束当前任务，不改变监控开关。如果全局监控及房间监控仍开启，
  下轮检测到开播后可能立即开始新录制；要保持停止应选择暂停监控。
- 关闭房间监控、编辑时关闭监控、删除房间，均会等待对应录制任务退出，不影响其他房间。
- 中断录制保留分片，不自动合并；录制和合并期间不能修改房间的平台、房间号。

接口：`POST /api/rooms/{id}/recording/start`，
`POST /api/rooms/{id}/recording/stop`（请求体 `{"disable_monitor": true}`）。
任务检查、准备、停止和合并状态通过原有 `GET /api/recording-status` 返回。

### 录制健康检测

三个平台的 FFmpeg 录制进程共用健康检测，每 5 秒观察当前分片的文件大小，
并持续读取 FFmpeg `-progress pipe:1` 的 `out_time_us`。文件增长和媒体时间推进都正常才视为健康；
单纯的 `progress=continue` 心跳、重复时间戳或无效时间值不会重置超时。
这不是内容质量检测，不判断画面是否黑屏、静帧或音频是否静音。

设置页新增以下项目，保存到 SQLite，旧数据库启动时自动补充字段：

- `health_check_enabled`：默认开启，关闭后仍排空进度管道，但不因健康超时重启进程。
- `health_startup_timeout_seconds`：启动宽限，默认 60 秒，范围 15 至 3600 秒。
- `health_stall_timeout_seconds`：文件不增长或媒体时间不推进的超时，默认 60 秒，同上范围。
- `health_max_restarts`：每场录制自动恢复的预算，默认 3 次，范围 0 至 20；0 表示检测异常后直接暂停。

达到超时后，终止旧 FFmpeg（等待退出，必要时强制结束），保留已有非空分片，
重新检测开播并获取新的流地址，等待 5 至 30 秒后使用新的分片编号续录。
同一场录制不重置日志和计时。检查/获取流的超时各为 30 秒；确认下播则结束。
超过恢复预算后关闭该房间监控、标记录制中断并保留全部分片，不自动合并。
可重新启用房间监控，或手动立即录制开始新的一场；手动录制不自动打开监控。
全局停止、单房间停止、磁盘保护和程序退出都会同时回收进度读取、检测与 FFmpeg 任务。

录制状态接口包含 `health`（健康状态、当前分片大小、文件/媒体进度空闲秒数、恢复次数、最近异常），
前端显示于「录制健康」列。每次健康异常都会写入运行日志；累计恢复次数和最近一次原因
保存到 `live_room_log.health_restart_count` / `health_last_error`，可在录制日志页查看，重启不丢失。
健康检测设置修改对活动录制的下一次检查生效，不更改文件命名和保存路径。
若恢复时直播流从 TS 切换为 FLV（或相反），自动后处理保留两种格式的全部分片，
不只合并其中一部分；可在视频处理模块中统一转码后手动合并。

录制后处理仅使用 FFmpeg `-c copy` 合并分片，保留原 TS / FLV 格式和音视频编码，
不压缩、不转码，也不额外封装 MP4。合并结果保留在本地保存目录，
视频名称、路径、大小和时长直接登记到 SQLite。成功登记后清理分片；失败时保留原文件。
设置页文件名示例采用 `.ts`，实际扩展名由直播源的分片格式决定。
前端「视频文件」页通过 `GET /api/videos/{id}/file` 打开本地视频，支持范围请求。
修改保存目录不会影响旧视频访问。历史外部视频地址保留，新录制不再上传到对象存储。
已有 SQLite 数据库会在启动时自动补充视频本地路径字段，不删除旧记录或配置表。

## 房间独立录制设置

直播间操作列的滑杆图标打开该房间的录制设置。保存目录、命名规则、清晰度、
检查周期和分片时长可以逐项覆盖；默认全部继承全局。点击「全部继承全局」后保存即可恢复，
不会改动其他房间。保存目录浏览与设置页使用同一服务端目录选择器及访问限制。
命名规则支持现有变量和子目录，例如 `{remark}/{timestamp}`，弹窗会显示实际路径示例。

全局设置新增默认清晰度和定时独立分片。清晰度按平台实际提供的档位选择最高、高、中或最低，
不是固定分辨率；B 站和斗鱼从平台返回的档位中选择，没有档位信息时使用平台默认流。
检查周期按房间分别计时，范围 1 至 86400 秒；保存设置会唤醒该房间检查。

分片时长为 0 时沿用原行为：不按时间切割，结束后合并断流分片。
设置为 1 至 1440 分钟时，使用 FFmpeg 连续录制并按关键帧切割，实际时长可能稍长于设定值。
各分片独立保留并登记到视频列表，不再自动合并成大文件；手动中断也登记已有非空分片，
中断场景不额外等待时长探测，登记时长为 0。健康恢复预算耗尽时优先保留原始文件，仍不自动合并。

路径、命名、清晰度和分片配置在每场录制开始时固定，修改后对下一场录制生效；
检查周期保存后即可参与调度。磁盘保护与健康检测继续使用全局规则，并保持动态生效，
独立目录同样纳入磁盘保护。配置保存至 SQLite，旧数据库启动时自动升级，无需重建。
后端模块位于 `app/modules/room_settings/`，接口为 `/api/rooms/{id}/recording-settings`，
提供读取、完整保存、恢复继承和 `/preview` 预览。

## 视频处理

前端「视频处理」下有「转码」和「合并」标签页，与录制后的自动分片合并完全独立。
文件选择窗口沿用设置页的目录浏览，可进入文件夹、多选视频、跨目录添加文件；
选择的是后端电脑已有文件，不会上传浏览器电脑上的文件。沿用本机访问限制，未开放远程目录浏览。

转码支持 copy（只重新封装）、H.264 / H.265 软件编码以及 Intel QSV、NVIDIA NVENC、
AMD AMF、Apple VideoToolbox 编码器。下拉框根据 FFmpeg 编译支持禁用不可用项；
硬件编码还需要相应显卡和驱动，初始化失败会在任务中显示具体错误，不会静默切换编码器。
输出格式支持 MP4、MKV、TS；编码与容器不兼容时保留源文件并显示 FFmpeg 错误。
默认、高质量、快速压缩配置分别使用 CRF 23 / 18 / 28 和 medium / slow / fast 软件预设；
硬件编码分别使用 4 / 8 / 2 Mbps 视频码率。copy 不使用质量配置。
转码结果命名为 `原文件名_编码器.扩展名`，可保存到各自源目录或统一选择的输出目录。
支持跳过或覆盖已有结果、保留元数据、成功后移除源文件；移除需再次确认，
跳过、失败、取消或处理期间变化的源文件不会删除。

合并按列表顺序进行，可用上下箭头调整顺序。至少选择两个视频，音视频编码、分辨率、
音轨参数须一致，否则先统一转码再合并。使用 FFmpeg concat 与 `-c copy`，不重新编码。
可指定输出名称、目录、格式，选择保留元数据或合并同名 ASS / SRT 弹幕字幕文件；
每个视频须有相同格式的同名字幕，按视频时长平移字幕时间，输出为合并视频同名旁挂字幕。
此选项不把弹幕烧录进视频，也不合并原始弹幕 XML / JSON。

任务显示状态、百分比、结果路径和错误，可取消运行中及排队中的任务。
高频进度更新将轮询从 1.5 秒改为 0.5 秒。后台单任务串行处理，最多 10 个活动任务，
避免占满 CPU / GPU；最多保留 100 条当前进程任务记录，重启不恢复队列或历史。
正在录制或自动合并的文件不能处理。输出先写入临时目录，成功并验证后才替换目标文件；
失败或取消会清理临时文件，已成功完成的批次输出保留。关闭服务会中断视频处理并等待 FFmpeg 退出。
结果作为独立文件保存在选择的目录，不伪造直播间关联或登记成直播录制日志。
FFmpeg 和同目录的 FFprobe 必须可用。接口位于 `/api/processing`，包含文件浏览、
编码器检测、任务列表、提交与取消任务。

后端回归验证：`python -m unittest discover -s tests -v`（使用独立临时数据库）。

## 运行日志与故障诊断

直播间操作列的「运行日志」按钮打开当前房间日志弹窗；原有「录制日志」仍用于查看历次录制与视频。
弹窗支持级别和关键词筛选、自动刷新/暂停、跟随最新、展开异常堆栈、复制单条日志；
「查看全部」进入独立运行日志页并保留房间关联。全局页额外支持平台、房间及时间筛选和历史加载。
录制记录、视频处理任务也有对应运行日志入口。房间按 SQLite 内部 ID 关联，修改主播名或备注不影响查询。

日志保存到数据目录的 `logs/runtime.jsonl`，EXE 使用 EXE 数据目录，不写临时解压目录。
默认每份约 10 MiB，保留 5 份历史加当前文件（总计约 60 MiB，加单条记录余量），
可在 `config.yaml` 的 `logging` 下设置 `max_file_mb`（1 至 100）和 `backups`（1 至 10），重启生效。
保留控制台输出；文件写入在独立线程执行，队列最多 2000 条，内存尾部最多 1000 条。
队列满时不阻塞录制，页面和诊断结果会提示丢弃数量；文件不可写时保留内存日志并显示告警。
关闭服务等待队列写入完成。文件轮转后的过期历史不会永久保留。

日志记录结构化的 `room_id`（内部 ID）、`platform_room_id`（平台房间号）、`recording_log_id` 和
`processing_job_id`，不依靠解析主播名来识别房间。对 Cookie、认证头、已配置的敏感值、
URL 的路径/查询签名等执行脱敏，异常堆栈也执行同样处理。录制 FFmpeg 的错误输出持续排空，
仅保留最后 4 KiB 关键内容，不会因为错误输出管道积压而卡住录制。
自动刷新周期为 2 秒，前端单次最多 200 条，最多显示 1000 条；可通过时间筛选缩小历史范围。
单条消息最多保留 8000 字符、异常堆栈尾部最多 16000 字符，总记录限制为 64 KiB；超出时标注内容已截断。
只读取本模块新生成的 JSONL 文件，不导入旧的 `.log` / `.err` 原始文件。

「故障诊断」包括：

- SQLite 连接和只读查询、FFmpeg / FFprobe 运行与版本、磁盘状态、日志保存状态和任务数量。
- 默认不写入录制目录；勾选临时写入测试才创建并清理临时文件，不创建保存目录。
- 平台连接测试按选中的已有房间主动执行，不开始录制、不返回直播流地址。
- 硬件编码器列表只代表编译支持；实际编码测试由用户主动执行，使用短合成画面输出到空设备。
- 诊断命令有超时并回收子进程，同时仅允许一项主动诊断运行。
- 最近 1000 条警告/错误按原因、房间、任务和消息合并，显示次数、建议及相关日志入口。
  事件列表是近期历史，不代表故障当前仍存在，也不会自动认定 Cookie 失效或自动修复。

导出前显示 ZIP 内容清单和房间/时间范围，包含最多 500 条匹配的脱敏日志、录制设置摘要、
当前任务状态和上次手动环境检查结果。导出额外隐藏数据目录、保存目录及用户主目录前缀，
不包含 Cookie、完整配置文件、数据库、录制视频或任意目录文件。
日志仍可能含用户填写的非凭据文本；对外分享前请检查诊断包。

本模块接口统一在 `/api/system`：`GET /logs`、`GET /issues`、`POST /diagnostics`、
`POST /diagnostics/platform/{room_id}`、`POST /diagnostics/encoder` 和 `POST /diagnostics/export`。
沿用目录浏览的本机客户端与页面来源检查，未开放无认证的局域网访问；全局录制等原有接口不变。
后端代码归属 `app/modules/observability/`，日志上下文与启动配置在 `app/core/`。
